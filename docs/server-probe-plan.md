# 私有服务器探针与启用转发

状态：用户已确认并要求开始；第一步基础实现验证中。2026-10-26。

## 目标与范围

节点监控提供“转发节点 / 服务器探针”两个标签。用户复制安装命令到 VPS 后注册私有探针，查看基本资源监控，需要时启用转发。共用一个 Agent、一个服务器身份，不收集 SSH 凭证，不执行任意远程 Shell。

第一版不包含历史图表、告警、远程终端和批量执行命令。管理员在探针页面也仅查看自己安装的探针；现有转发节点权限保持兼容。

## 既有依据

- NodeServiceImpl.createNode/getAllNodes 已有节点所有者和授权节点机制，但管理员创建节点 owner 为 null，管理员列表全量可见，不能直接作为私有探针权限规则。
- WebSocketInterceptor 按节点 secret 验证连接，现有 Agent 已能上报 IPv4/IPv6 和系统资源，可复用。
- install.sh 当前接收固定节点密钥、写入 config.json 并创建 systemd 服务；需增加短期一次性令牌注册流程。
- 发布沿用 AGENTS.md 与 docs/frontend-release.md，不使用 CI。

- [ ] 2. Agent 监控模式：首次注册并持久化身份；监控模式不上转发监听，不处理转发配置命令；认证的启用操作与重启后状态一致。验证注册重放、过期、断线和重启。
- [ ] 3. 安装流程：复用 install.sh 和现有构建发布方式，生成本人一键命令。已有转发 Agent 不被误覆盖；安装失败可明确反馈。
