# 私有服务器探针与启用转发

状态：第一版实现、本地验证与不可变资产发布完成。2026-10-26。

## 目标与范围

节点监控提供“转发节点 / 服务器探针”两个标签。用户复制安装命令到 VPS 后注册私有探针，查看基本资源监控，需要时启用转发。共用一个 Agent、一个服务器身份，不收集 SSH 凭证，不执行任意远程 Shell。

第一版不包含历史图表、告警、远程终端和批量执行命令。管理员在探针页面也仅查看自己安装的探针；现有转发节点权限保持兼容。

## 既有依据

- NodeServiceImpl.createNode/getAllNodes 已有节点所有者和授权节点机制，但管理员创建节点 owner 为 null，管理员列表全量可见，不能直接作为私有探针权限规则。
- WebSocketInterceptor 按节点 secret 验证连接，现有 Agent 已能上报 IPv4/IPv6 和系统资源，可复用。
- install.sh 当前接收固定节点密钥、写入 config.json 并创建 systemd 服务；需增加短期一次性令牌注册流程。
- 发布沿用 AGENTS.md 与 docs/frontend-release.md，不使用 CI。

## Agent 监控模式进度

Agent 配置新增 probe_mode（缺省 false，旧节点保持原行为），监控模式先运行 WebSocket 系统上报，等待启用命令后才启动原有 gost 服务。监控期间拒绝转发配置命令；EnableForwarding 先以 0600 临时文件、sync、rename 保存模式，再解除等待，重复命令可重试。版本源码调整为 2.0.17-beta，尚未发布安装资产。

本地验证：Go 1.25 容器运行主程序 go build 与 x/socket 全部测试，通过。测试覆盖阻止转发命令、配置缺失不启用、模式/密钥及其他字段持久化、文件权限、重复启用，以及等待启用后才放行服务启动。使用临时 -modfile -mod=mod，未修改仓库依赖。现有安装脚本仍未接入监控注册；后端启用接口、启动就绪反馈、端到端启用与重启联调仍待完成，不能作为可用功能交付。

## 注册与启用 API 阶段

新增 /probe/token、/probe/list、/probe/register、/probe/activate；仅 register 免 JWT，使用 15 分钟一次性令牌，令牌兑换与节点插入同事务。令牌/独立密钥不进入请求日志。本人鉴权启用，需在线、Agent>=2.0.17-beta，等待 ForwardingStatus ready 后才切换模式并授权转发；未就绪或掉线保留探针身份、可重试。不持数据库事务等待 Agent。

## 安装脚本阶段

install.sh 增加 -p 面板 URL、-r 一次凭证、-n 名称参数，注册后写入独立 secret 与 probe_mode=true。已有程序/配置禁止覆盖，缺 python3 明确退出。探针下载固定 2.0.17-beta，读取其 SHA256SUMS 校验并验证版本，下载失败不在 VPS 源码编译；当前资产尚未发布，因此探针安装未开放使用。常规旧安装仍沿用既有版本。

Agent 支持带 http/https 的面板地址，WebSocket 对应 ws/wss，流量与配置上报保留面板协议；旧 host:port 兼容。注册响应异常输出不打印密钥。

本地验证：bash -n install.sh；提取脚本函数在临时目录模拟注册成功、已有安装拒绝、格式错误及过期凭证拒绝，全部通过。Go 本地主程序编译，x/socket 与 x/service 测试通过（临时 modfile）。尚未执行真实安装/系统服务联调；安装前令牌兑换成功但后续下载失败会留下离线记录，生命周期清理和重试体验待最终联调处理。
